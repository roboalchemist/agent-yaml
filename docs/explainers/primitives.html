agent-yaml primitives

Every workflow is built from the same small vocabulary. The forms are identical across adapters. Only the CLI-specific options change. Fields below are checked at parse time unless marked runtime.

Execution pipeline

One file is parsed, validated, and expanded, then each task becomes a subprocess call.

parser→ schema validation→ includes→ variables→ executor→ adapter→ agent CLI

Loops, validators, skip-if, when, and checkpoints hang off the executor. They act per task, after or before the subprocess.

Workflow fields top level

FieldTypeRequiredWhat it does
directorystringyesWorking directory for every task. ~ is expanded and the path must exist.
cli-agentstringnoopencode, claude, gemini, qwen, or codex. Defaults to claude.
cli-agent-configmapnoAdapter options: model, timeout, skip-confirmations, additional-dirs, mcp-config-file, raw-args.
environmentmapnoEnvironment variables inherited by every task.
template-variablesmapnoUser variables. Resolved in dependency order, and reference cycles are rejected.
includesmapnoReusable prompt fragments, either inline strings or paths to files.
ensuremapnoPre-flight checks for tools (found with shutil.which) and mcps.
tasklistyesThe task tree. Its shape controls scheduling.

Task fields

Any key that is not in this list is treated as a nested task name.

FieldTypeWhat it does
promptstringText sent to the agent CLI. Required unless the task groups children or runs a loop.
tasklist or mapNested tasks. A list runs in order, a map runs its keys concurrently in a ThreadPoolExecutor.
includelistNames from the top-level includes, appended to the prompt.
loopmapRuns the task once per item. See loops.
validatelistChecks run after the task exits 0. See validators.
retrymapmax-attempts and on-validation-failure: retry, fail, skip.
skip-ifmapfile-exists or file-contains, evaluated before the task runs.
whenstringExpression gate. An empty string skips the task.
envmapTask-level environment variables.
directorystringTask working directory, relative to the workflow directory.
cli-agent-configmapPer-task adapter options, merged over the workflow level.
on-errorstringfail, continue, or skip. Overrides the workflow default.

Shape controls scheduling

task:
  - setup:            # runs first
      prompt: "Create the work directory"

  - review:           # these two run at the same time
      stats:  {prompt: "Write stats.md"}
      report: {prompt: "Write report.md"}

  - publish:          # runs after both finish
      task:
        - checksum: {prompt: "Write checksums.txt"}
        - index:    {prompt: "Write index.md"}

Loops

Five types. Each runs one task per item and exposes the item as {{loop.item}}.

typeIterates overRequiredItem fields
todo-listPending - [ ] items in a markdown filesourcetext, number, line
csvRows of a CSVsourceNamed columns, plus row
jsonArray in a JSON file, optionally nested via pathsourceObject fields, plus _index
jsonlOne JSON object per linesourceObject fields, plus _index
globFiles matching a patternpatternpath, filename, extension

Shared options

OptionTypeWhat it does
checkpoint-filestringJSON progress file. Template variables are expanded to an absolute path.
resumeboolLoad the checkpoint and continue after the last completed item.
retrymapmax-attempts, and on-failure: skip, retry, abort.
workersintItems run concurrently. Applies to csv, json, and jsonl. todo-list and glob stay sequential.
directory-poollistExisting directories assigned round-robin to workers.
git-worktreesmapOne worktree per worker: base, branch-field, name-template, cleanup.

Type-specific filters

columns and filter: {column, value} for csv. path and filter for json. Filters compare exact values.

task:
  - summarize-rows:
      loop:
        type: csv
        source: "{{directory}}/rows.csv"
        workers: 4
        retry: {max-attempts: 3, on-failure: retry}
        checkpoint-file: "{{directory}}/state/summaries.json"
        resume: true
      prompt: "Summarize {{loop.item.name}} and write {{directory}}/out/{{loop.item.name}}.md"
      validate:
        - file-not-empty: "{{directory}}/out/{{loop.item.name}}.md"

Validators

Validators run after a task exits 0 and check the artifacts on disk. All validators run even when one fails, so a single pass reports every problem.

ValidatorConfigPasses when
file-existsstring pathThe path exists, file or directory.
file-not-emptystring pathThe path exists and its size is greater than zero.
contains{file, text}The file contains the text as a substring.
json-validstring pathThe whole file parses as JSON.
yaml-validstring pathThe whole file parses with yaml.safe_load.
command{cmd, file?, timeout?}The command exits 0. {file} in cmd is replaced with the file path. Timeout defaults to 30s.

Validator paths resolve against the agent-yaml process working directory, not the workflow directory. Use absolute paths or {{directory}}/....

task:
  - write-report:
      prompt: "Write report.md with a ## Summary section"
      validate:
        - file-exists: "{{directory}}/report.md"
        - contains: {file: "{{directory}}/report.md", text: "## Summary"}
        - command: {cmd: "python3 scripts/lint.py {file}", file: "{{directory}}/report.md", timeout: 60}
      retry:
        max-attempts: 3
        on-validation-failure: retry

Variables

Interpolation happens into prompts, paths, environment values, and loop configuration.

VariableValue
{{directory}}Absolute workflow directory.
{{gitroot}}Nearest ancestor containing .git/, otherwise {{directory}}.
{{datetime}}ISO-8601 timestamp with the local offset, evaluated once per run.
{{user}}USER, USERNAME, or LOGNAME, else unknown.
{{env.NAME}}Variable from the merged environment.
{{loop.index}}0-based item index.
{{loop.total}}Number of items.
{{loop.remaining}}Items left, including the current one.
{{loop.item}}Current item. Fields depend on the loop type.
{{loop.worker.id}}Worker id for parallel loops.
{{loop.worker.directory}}Worker directory with directory-pool or git-worktrees.

Precedence

Later wins:

system env  <  --env-file  <  workflow environment:  <  task env:  <  CLI --var

User variables live under template-variables and may reference each other. Reserved names cannot be overridden. --var key=value overrides user variables and arrives as a string.

Where each lives

Schema and fields

agent_yaml/validator.py enforces required fields, task shape, loop and validator config, and adapter option names.

Loops and checkpoints

agent_yaml/loops.py implements the five types, workers, directory pools, worktrees, and checkpoint files.

Validators

agent_yaml/task_validators.py implements the six checks and the command runner.

Variables and includes

agent_yaml/variables.py, agent_yaml/utils.py, and agent_yaml/includes.py handle interpolation and fragment resolution.

Execution

agent_yaml/executor.py and agent_yaml/cli.py walk the task tree and call the adapter.

Adapter translation

agent_yaml/adapters/ maps config keys to each CLI's flags.
