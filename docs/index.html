1Overview

A workflow is one YAML file. Each task in it becomes one subprocess call to an agent CLI. Steps hand each other files, and validators decide whether a step actually produced what it claimed.

parser→ schema validation→ includes→ variables→ executor→ adapter→ agent CLI

Loops, validators, skip-if, when, and checkpoints act on tasks around that subprocess. The shape of the task tree decides what runs in order and what runs at the same time.

The practical effect: the same file runs under OpenCode, Claude Code, Gemini, Qwen, or Codex. You change cli-agent, and the steps stay the same.

2Install and first run

Install from the repository. There is no PyPI release yet. You need Python 3.8 or newer and at least one agent CLI on PATH.

pip install "git+https://github.com/roboalchemist/agent-yaml.git"
agent-yaml --help

Write a workflow, check it, then run it:

directory: /tmp/hello
cli-agent: opencode
cli-agent-config:
  skip-confirmations: true

task:
  - write-file:
      prompt: "Create hello.txt containing: hello from agent-yaml"
mkdir -p /tmp/hello
agent-yaml validate hello.yaml        # parse, schema, and CLI check. No agent calls.
agent-yaml run hello.yaml --dry-run   # print the exact command
agent-yaml run hello.yaml             # call the agent

Run validate and --dry-run first. A wrong model name or an option the CLI rejects shows up before you spend tokens.

3The workflow file

Nine top-level fields. Only two are required.

FieldTypeRequiredMeaning
directorystringyesWorking directory for every task. ~ expands, and the path must exist.
tasklistyesThe task tree.
cli-agentstringnoopencode, claude (default), gemini, qwen, or codex.
cli-agent-configmapnomodel, timeout, skip-confirmations, additional-dirs, mcp-config-file, raw-args.
environmentmapnoEnvironment variables inherited by every task.
template-variablesmapnoUser variables, resolved in dependency order.
includesmapnoReusable prompt fragments.
ensuremapnoPre-flight tools checks.
on-errorstringnofail (default), continue, or skip.

Validation rejects unknown adapter options, missing required fields, and malformed task trees before any subprocess starts.

4Task tree

A list runs in order. A mapping runs its keys concurrently. The two nest freely.

directory: /tmp/docs-example
cli-agent: opencode

task:
  - prepare:
      prompt: "Write plan.md"

  - execute:
      collect: {prompt: "Write data.csv"}
      analyze: {prompt: "Write analysis.md"}

  - publish:
      task:
        - checksum: {prompt: "Write checksums.txt"}
        - index:    {prompt: "Write index.md"}

prepare runs first. collect and analyze run together. Then checksum and index run in order.

A list item must be a named task (name: {...}). A bare - {prompt: "..."} entry is rejected by validation.

Meta fields on a task: prompt, task, loop, include, validate, retry, skip-if, when, env, directory, cli-agent-config, on-error. Any other key is a child task. A task with a prompt is a leaf, and sibling keys beside it are ignored, so keep grouping and prompting in separate tasks.

5Variables

Five variables are injected for you.

VariableValue
{{directory}}Absolute workflow directory.
{{gitroot}}Nearest ancestor with .git/, else {{directory}}.
{{datetime}}ISO-8601 timestamp with offset, fixed for the run.
{{user}}USER, USERNAME, or LOGNAME, else unknown.
{{env.NAME}}Variable from the merged environment.

Define your own under template-variables. They may reference each other, and cycles are rejected. Names use hyphens, not underscores.

directory: /tmp/docs-example
cli-agent: opencode

template-variables:
  service: billing-api
  docs-dir: "{{gitroot}}/docs"
  output: "{{docs-dir}}/{{service}}.md"

task:
  - write:
      prompt: "Write {{output}}"

--var key=value overrides a user variable and arrives as a string.

An undefined variable interpolates to an empty string. Validation does not catch it, and the prompt silently loses a path.

6Includes

Includes are prompt fragments you reuse across tasks. A name defined under includes: is inline text. Any other string is a file path, and a missing file is an error.

directory: /tmp/docs-example
cli-agent: opencode

includes:
  use-subagents: "Use sub-agents for independent parts of this task."
  always-validate: "Validate every change before finishing."

task:
  - review:
      prompt: "Review the diff and write review.md"
      include: [use-subagents, always-validate]

Included text is appended to the prompt before interpolation, so variables inside a fragment resolve against the task that includes it. Include cycles are rejected.

7Loops

A loop turns one task into one task per item. Five sources.

TypeIterates overRequiredItem fields
todo-listPending - [ ] items in markdownsourcetext, number, line
csvCSV rowssourcenamed columns plus row
jsonJSON array, optionally nestedsourceobject fields plus _index
jsonlOne JSON object per linesourceobject fields plus _index
globFiles matching a patternpatternpath, filename, extension

Every loop accepts checkpoint-file, resume, retry, directory-pool, and git-worktrees. workers only parallelizes csv, json, and jsonl.

directory: /tmp/docs-example
cli-agent: opencode

task:
  - prepare:
      prompt: "Write rows.csv with a name column"

  - summarize:
      loop:
        type: csv
        source: "{{directory}}/rows.csv"
        workers: 4
        retry: {max-attempts: 3, on-failure: retry}
        checkpoint-file: "{{directory}}/state/summaries.json"
        resume: true
      prompt: "Summarize {{loop.item.name}} into {{directory}}/out/{{loop.item.name}}.md"
      validate:
        - file-not-empty: "{{directory}}/out/{{loop.item.name}}.md"

Loop variables: {{loop.index}} (0-based), {{loop.total}}, {{loop.remaining}}, {{loop.item}}. With a worker directory you also get {{loop.worker.id}} and {{loop.worker.directory}}.

Checkpoints make a loop resumable. The file records the last completed index, so rerunning the same command skips finished items. agent-yaml run --resume is a no-op. Resumption is driven by resume: true in the loop.

8Validators

A validator runs after the task exits 0 and inspects what it produced. This is the difference between an agent saying it finished and the file existing.

ValidatorConfigPasses when
file-existsstring pathThe path exists.
file-not-emptystring pathThe path exists and is not empty.
contains{file, text}The file contains the text.
json-validstring pathThe file parses as JSON.
yaml-validstring pathThe file parses as YAML.
command{cmd, file?, timeout?}The command exits 0. {file} is substituted.
 
directory: /tmp/docs-example
cli-agent: opencode

task:
  - report:
      prompt: "Write report.md with a ## Summary section"
      validate:
        - file-exists: "{{directory}}/report.md"
        - contains: {file: "{{directory}}/report.md", text: "## Summary"}
        - command: {cmd: "python3 -c \"print('ok')\"", timeout: 10}
      retry:
        max-attempts: 3
        on-validation-failure: retry

All validators in the list run, even after one fails, so a single pass reports every problem.

Validator paths resolve against the agent-yaml process working directory, not the workflow directory. Use absolute paths, usually {{directory}}/....

9Conditionals

skip-if is an idempotency check that runs before the task. when is an expression gate. Skip-if is evaluated first.

directory: /tmp/docs-example
cli-agent: opencode

task:
  - deploy:
      skip-if:
        file-exists: "{{directory}}/deployed.flag"
      when: "{{environment}} == 'production' and {{tests_passed}}"
      prompt: "Deploy and write deployed.flag"
GateOptionsBehavior
skip-iffile-exists, file-containsA missing file for file-exists means do not skip.
when==, !=, <, >, <=, >=, and, or, not, in, not inAn empty expression, an undefined variable, or a bad expression skips the task.

--var values are strings. --var n=5 against {{n}} > 3 compares a string to a number, fails internally, and skips the task. Write {{n | int}} > 3 when the value comes from the CLI.

10Errors and retries

Three levels, each with its own setting.

LevelSettingValues
Workflow or taskon-errorfail (default), continue, skip
Loop itemretry.on-failureskip, retry, abort
Validatorretry.on-validation-failureretry, fail, skip
 
directory: /tmp/docs-example
cli-agent: opencode
on-error: continue

task:
  - flaky:
      prompt: "Write output.txt"
      validate:
        - file-not-empty: "{{directory}}/output.txt"
      retry:
        max-attempts: 3
        on-validation-failure: retry

In a list, fail stops the remaining tasks. In a parallel group, tasks already submitted still run, pending ones are cancelled, and the run exits non-zero. Cancellation is best effort.

11Adapters

Adapters translate the same config keys into each CLI's flags. Pick one with cli-agent.

AdapterSkip confirmationsModelNotes
opencode--auto--model provider/modelRuns opencode run, with --standalone by default.
claude--dangerously-skip-permissions--modelAliases such as sonnet-4.5 are translated.
gemini--yolo--model--include-directories from additional-dirs.
qwen--yolo--model--include-directories from additional-dirs.
codex--full-auto-mUses only the first additional-dirs entry.
 
directory: /tmp/docs-example
cli-agent: claude
cli-agent-config:
  model: sonnet-4.5
  timeout: 900
  skip-confirmations: true
  additional-dirs: ["/tmp"]

task:
  - work:
      prompt: "Write work.txt"

raw-args appends flags verbatim after the translated ones. Use it when a CLI changes and the adapter has not caught up. Adding an adapter means subclassing BaseAdapter, implementing build_command() and check_available(), and registering it.

12Command line

FlagEffect
--dry-runPrint the plan and every argv. No subprocess. The CLI availability check still runs.
--debugPrint the full command per task and stream agent output.
--verboseProgress logging to stderr.
--var key=valueOverride a template variable. Repeatable. Values arrive as strings.
--env-file PATHLoad a dotenv file. Repeatable, later files win.
--directory DIROverride the workflow directory.
--cli-agent NAMEOverride the adapter for this run.
--model MODELModel for every task, over the workflow and task config.
 
agent-yaml validate workflow.yaml
agent-yaml run workflow.yaml --dry-run
agent-yaml run workflow.yaml --cli-agent codex --model gpt-5 --var service=billing
agent-yaml run workflow.yaml --env-file .env.local --verbose

Exit codes: 0 success, 1 any failure (parse, validation, or task).

Environment precedence, later wins:

system env  <  --env-file  <  environment:  <  task env:  <  --var

13Visual runner

agent-yaml serve starts a local console for browsing, running, and watching workflows.

agent-yaml serve                                  # http://127.0.0.1:8765
agent-yaml serve --port 9000 --reload             # different port, autoreload
agent-yaml serve --db /tmp/runs.sqlite            # override the database

It discovers examples/*.yaml and tasks/*.yaml relative to the server's working directory, draws the stage graph on a WebGL2 canvas, and streams execution events over SSE. Runs, node states, and interval or cron schedules persist in SQLite.

EndpointPurpose
GET /api/workflows/discoverCatalog entries with agent, directory, and stage count.
POST /api/workflows/importImport a workflow path and project its graph.
POST /api/workflows/{id}/runsStart a run, optionally dry.
GET /api/runs/{id}/streamLive SSE callbacks.
GET/POST/PATCH/DELETE /api/schedulesInterval and cron schedules.

14Debugging

Work in this order. Each step costs less than the next one.

  1. agent-yaml validate wf.yaml catches schema errors and a missing CLI.
  2. agent-yaml run wf.yaml --dry-run shows the argv for every task, including the model.
  3. agent-yaml run wf.yaml --debug prints that argv and streams the agent output.
  4. Read the file the task was supposed to write. If it is missing, the prompt asked for prose instead of an artifact.
SymptomCauseFix
cli-agent 'x' not availableThe CLI is not on PATH.Install it or pass --cli-agent.
Variable resolves to emptyUndefined variable, or a hyphen typo.Check the name, then --dry-run.
Task never runsskip-if matched, or when was falsy.Check the flag file and the expression types.
Agent ran, file missingThe prompt asked for chat output.Ask for a file and add a validator.
TimeoutDefault is no timeout.Set cli-agent-config.timeout.

15Limits and gotchas

  • Agent output is never parsed. If a step must prove something, it writes a file and a validator checks it.
  • workers does nothing for todo-list and glob.
  • agent-yaml run --resume is accepted but does nothing. Use resume: true on the loop.
  • ensure.mcps is a warning-only stub. Only ensure.tools is enforced.
  • A list item under task: must be named. - {prompt: "..."} is rejected.
  • A task with both prompt and child keys runs only the prompt. The children are ignored.
  • The Codex adapter emits flags that recent codex-cli releases reject. Use raw-args.
  • Parallel cancellation is best effort. Already-running tasks finish.
  • There is no nested loop support. A loop task cannot start another loop.
