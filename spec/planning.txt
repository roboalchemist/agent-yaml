- Configurable log levels (DEBUG, INFO, WARN, ERROR)

## Full Jinja2 Support
Expand template variable support to full Jinja2 syntax:
- Filters: `{{var | upper}}`, `{{var | default('fallback')}}`
- Conditionals: `{% if condition %}...{% endif %}`
- String manipulation: `{{var | replace('old', 'new')}}`
- Math operations: `{{count + 1}}`

**Use cases:**
- Conditional execution without branching YAML
- Dynamic prompt construction
- String formatting
- Branching logic via template conditionals

Example:
```yaml
template-variables:
  environment: "production"

task:
  - deploy:
      prompt: "{% if environment == 'production' %}Deploy carefully{% else %}Deploy quickly{% endif %}"
```

## ✅ COMPLETED: Validators (v0.2.0)
Post-task validation mechanisms implemented with 6 validator types:
- ✅ file-exists: Check if file path exists
- ✅ file-not-empty: Check if file has content
- ✅ contains: Check if file contains text substring
- ✅ json-valid: Validate JSON syntax
- ✅ yaml-valid: Validate YAML syntax
- ✅ command: Run custom validation script

Example:
```yaml
task:
  - analyze:
      prompt: "Analyze codebase and write to analysis.md"
      validate:
        - file-exists: "analysis.md"
        - file-not-empty: "analysis.md"
        - contains:
            file: "analysis.md"
            text: "## Summary"
```

## ✅ COMPLETED: Retry Mechanisms (v0.2.0)
Retry logic implemented with validation failure handling:
- ✅ max-attempts: Number of times to retry a task
- ✅ on-validation-failure: retry | skip | fail
- ✅ Loop-level retry: Works with all loop types

Example:
```yaml
task:
  - flaky-task:
      prompt: "Generate report"
      validate:
        - file-exists: "report.md"
      retry:
        max-attempts: 3
        on-validation-failure: retry
```

Note: Validators run after task completes. If validation fails, the entire task prompt is re-executed.

## Task-Level Configuration
Add per-task configuration options to override global settings:
- timeout: Per-task timeout override
- working-dir: Override working directory for specific tasks
- mcps: Specify which MCPs to enable for this task
- skip-if: Conditional execution based on conditions
- env: Task-specific environment variables

Example:
```yaml
task:
  - my-task:
      prompt: "..."
      config:
        timeout: 600
        working-dir: "./sub"
        mcps: [notion, linear]
        skip-if: "{{some-condition}}"
```
